# 项目愿景与决策记录

## 愿景

用 LLM / AI Agent 作曲、编曲，用代码合成真实乐器的声音，组合成乐队编制（先摇滚乐队，远期小型交响乐团）。
可以编辑曲谱，也可以调整每种乐器的演奏细节。

## 整体架构（已认可）

```
LLM Agent（作曲/编曲）
   │  输出符号化乐谱（文本 DSL）
   ▼
① 乐谱表示层   音符、和声、配器、力度、演奏法
   ▼
② 演奏渲染层   谱面 → 演奏：时值微调、力度曲线、颤音、滑音、连奏
   ▼
③ 声音合成层
   ▼
④ 混音层       声像、EQ、压缩、混响、母带
   ▲
⑤ 编辑界面     五线谱 + 钢琴卷帘 + 表情曲线，双向同步
```

- 走“符号化 + 合成”路线，不用端到端音频生成（Suno/Udio 类），因为后者无法编辑。
- LLM 只写自定义的中间 DSL（JSON/YAML），由代码编译成 MIDI / MusicXML。
- 数据模型分两层：**谱面**（作曲意图）和**演奏**（逐音的偏移和曲线）分开存储。
- 不同音源的演奏法接口不统一，需要抽象的演奏法层，再给每个音源写映射。

## 物理建模要点（摇滚乐队）

通用原则：
- 拆成“激励 → 共振体 → 辐射/拾音”，各部分单独建模、单独校准。
- 补齐“不理想”的细节：非谐性（色散）、随频率变化的损耗、双偏振和拍频、张力调制（音高下滑）、碰撞非线性（打品、slap、军鼓响弦）。
- 每个音加入微小随机扰动，避免“机关枪效应”。
- 保留振动状态，新的激励作用在当前状态上（物理建模相对采样的最大优势）。
- 加入非音乐的声音：刮弦、滑弦、踏板声等。
- 校准：用真实单音录音拟合非谐系数和各泛音衰减；用可微分模型（JAX）+ 多分辨率 STFT 损失自动拟合参数；最终以盲听 A/B 为准。
- 离线渲染，可以用较昂贵的模型和高过采样倍数。

各乐器方案和预期真实度：

| 乐器 | 方案 | 预期 |
|---|---|---|
| 电吉他 | 扩展 Karplus-Strong / 数字波导 + 拾音器模型 + 品碰撞；放大器用 WDF 电路建模，箱体用 IR 卷积 | ⭐⭐⭐⭐⭐ |
| Hammond / Rhodes | 转轮加法合成 + Leslie 模型 / 音叉 + 拾音器非线性 | ⭐⭐⭐⭐⭐ |
| 电贝斯 | 同吉他框架，加强非谐性、张力调制、slap/pop 碰撞 | ⭐⭐⭐⭐ |
| 嗵鼓、底鼓 | 圆膜模态合成（或 2D FDTD）+ 鼓腔耦合 + 音高下滑 | ⭐⭐⭐⭐ |
| 军鼓 | 双鼓皮耦合 + 响弦碰撞非线性 | ⭐⭐⭐ |
| 钢琴 | 琴槌非线性 + 多弦耦合 + 音板 + 共鸣 | ⭐⭐⭐ |
| 镲片、踩镲 | 非线性板（von Kármán）或模态 + 非线性耦合 / 滤波噪声近似 | ⭐⭐ 最大短板，必要时临时用采样 |

工具候选：Faust（`physmodels`）、STK、JAX、numba、C++/Rust 渲染引擎、`chowdsp_wdf`。

建议的第一步：电吉他单弦模型 + 简单真空管失真 + 箱体 IR，顺便搭出模块化框架。

## 评测记录

- **2026-10-03 试点**（Sonnet，5 个任务 × 3 次，`evals/results/20261002-2329-sonnet-pilot/`）：15/15 最终通过校验；转写和修错任务 F1 全部 1.0；修改任务 12/12 项检查通过。
  - 最常见错误：鼓网格多写或少写一个字符（第一次检查时 6 个错误）。
  - 15 次里 12 次想用 python 筛选 `beat events` 的输出。
  - t1、t2、t4 对 Sonnet 太简单，分数到顶；还没有衡量“好不好听”。
- **2026-10-04 Haiku 下限**（规格和工具已按试点改进，`evals/results/20261003-2154-haiku-floor/`）：14/15 最终通过校验（失败的 1 次是评测框架问题：它用 `./.bin/beat` 调用，被权限拦下后放弃）；修改 12/12、修错 F1 ≈ 1.0、创作 8/8，但**转写 F1 只有 0.81–0.82**。
  - 校验能抓的错误 Haiku 最终都改好了（网格长度错误 329 个、记号错误 309 个，平均 6–8 轮），但花费和时间是 Sonnet 的 2–3 倍。
  - 失分全是**能通过校验的错误**：鼓击打放错了步（例如底鼓放在第 2 拍而不是第 2.5 拍；三连音叮叮镲被写进 16 步网格）；2.5 拍、6 拍这类时值被截成 2 拍、4 拍（没用连音线拼）；时值沿用导致四分音符写成八分音符。
  - 结论：网格记谱和“只能用连音线拼时值”对小模型代价很高，且错误会悄悄通过校验。这是对两项待决定改动（任意时值写法、按拍位写鼓）的有力证据。
- **2026-10-04 Haiku A/B：`hits` + `:b`**（`evals/results/20261004-0311-haiku-ab-hits/`，对照组为上一条）：t1 F1 0.82 → 0.95，t2 F1 0.81 → 0.98；6 次全部用 `hits`、无一次用 `grid`；平均用时约 10.5 → 5 分钟，花费 0.87 → 0.40 美元。
  - 剩余失分：一次把三连音位置写成 `1.667`（已改为报错）；个别鼓件放错、2.5 拍的音仍被写短一次。
  - 评测框架问题：Agent 用 `.bin/beat` 调用被拦截，已放行该写法并在提示里说明直接用 `beat`；受影响的那次已重跑。
