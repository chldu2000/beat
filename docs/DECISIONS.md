# 项目愿景与决策记录

## 愿景

用 LLM / AI Agent 作曲、编曲，用代码合成真实乐器的声音，组合成乐队编制（先摇滚乐队，远期小型交响乐团）。
可以编辑曲谱，也可以调整每种乐器的演奏细节。

## 整体架构（已认可）

```
LLM Agent（作曲/编曲）
   │  输出符号化乐谱（文本 DSL）
   ▼
① 乐谱表示层   音符、和声、配器、力度、演奏法
   ▼
② 演奏渲染层   谱面 → 演奏：时值微调、力度曲线、颤音、滑音、连奏
   ▼
③ 声音合成层
   ▼
④ 混音层       声像、EQ、压缩、混响、母带
   ▲
⑤ 编辑界面     五线谱 + 钢琴卷帘 + 表情曲线，双向同步
```

- 走“符号化 + 合成”路线，不用端到端音频生成（Suno/Udio 类），因为后者无法编辑。
- LLM 只写自定义的中间 DSL（JSON/YAML），由代码编译成 MIDI / MusicXML。
- 数据模型分两层：**谱面**（作曲意图）和**演奏**（逐音的偏移和曲线）分开存储。
- 不同音源的演奏法接口不统一，需要抽象的演奏法层，再给每个音源写映射。

## 物理建模要点（摇滚乐队）

通用原则：
- 拆成“激励 → 共振体 → 辐射/拾音”，各部分单独建模、单独校准。
- 补齐“不理想”的细节：非谐性（色散）、随频率变化的损耗、双偏振和拍频、张力调制（音高下滑）、碰撞非线性（打品、slap、军鼓响弦）。
- 每个音加入微小随机扰动，避免“机关枪效应”。
- 保留振动状态，新的激励作用在当前状态上（物理建模相对采样的最大优势）。
- 加入非音乐的声音：刮弦、滑弦、踏板声等。
- 校准：用真实单音录音拟合非谐系数和各泛音衰减；用可微分模型（JAX）+ 多分辨率 STFT 损失自动拟合参数；最终以盲听 A/B 为准。
- 离线渲染，可以用较昂贵的模型和高过采样倍数。

各乐器方案和预期真实度：

| 乐器 | 方案 | 预期 |
|---|---|---|
| 电吉他 | 扩展 Karplus-Strong / 数字波导 + 拾音器模型 + 品碰撞；放大器用 WDF 电路建模，箱体用 IR 卷积 | ⭐⭐⭐⭐⭐ |
| Hammond / Rhodes | 转轮加法合成 + Leslie 模型 / 音叉 + 拾音器非线性 | ⭐⭐⭐⭐⭐ |
| 电贝斯 | 同吉他框架，加强非谐性、张力调制、slap/pop 碰撞 | ⭐⭐⭐⭐ |
| 嗵鼓、底鼓 | 圆膜模态合成（或 2D FDTD）+ 鼓腔耦合 + 音高下滑 | ⭐⭐⭐⭐ |
| 军鼓 | 双鼓皮耦合 + 响弦碰撞非线性 | ⭐⭐⭐ |
| 钢琴 | 琴槌非线性 + 多弦耦合 + 音板 + 共鸣 | ⭐⭐⭐ |
| 镲片、踩镲 | **先用采样**（已决定）；以后再尝试非线性板（von Kármán）或模态 + 非线性耦合 | ⭐⭐ 最大短板 |

工具候选：Faust（`physmodels`）、STK、JAX、numba、C++/Rust 渲染引擎、`chowdsp_wdf`。

建议的第一步：电吉他单弦模型 + 简单真空管失真 + 箱体 IR，顺便搭出模块化框架。（2026-10-05 已完成 v1 并设为默认，见上面的决定。）

### 电吉他模型的改进方向（v1 之后）

v1 试听“还可以”。下面是已知的可能改进，按大致优先级排列，还没有排期：

- **音色**：闷音段落高频偏少，chug 可能不够扎实（可以放宽闷音的高频损耗，或让闷音的起音更亮）；干净音色比旧版暗不少，主要是合成箱体 5.2 kHz 以上衰减得陡，可以调箱体或给 `clean` 加亮。
- **演奏法 v2**：`!sl`（滑弦，连续改变延迟长度）、`!bend`、`!vib`（分数延迟已用 Lagrange 插值，可以直接调制）、`!harm`（在泛音节点轻触弦）。
- **弦的物理细节**：双偏振和拍频；张力调制（重拨时音高先偏高再回落）；打品等碰撞非线性；各弦的非谐系数和衰减用真实录音校准。
- **非音乐的声音**：拨片刮弦、换把滑弦声、松手时的手指噪声。
- **拾音器**：琴颈 / 琴桥拾音器可选（例如放进 `model:`），单线圈和双线圈的谐振差别。
- **放大器和箱体**：用 WDF 做电路级的电子管建模（含供电下垂和随弹奏力度变化的动态）；换成录制的 IR，或让合成 IR 可选话筒位置。
- **分配到弦**：现在只看手位和不切断保持的音；以后可以允许在 `model:` 或记谱里指定弦或把位。
- **校准方法**：用可微分模型（JAX）+ 多分辨率 STFT 损失拟合真实单音录音，最终以盲听 A/B 为准。
- **贝斯**（2026-10-05 已换成弦模型，试听“挺不错”）：
  - 演奏方式：加拨片和 slap / pop（需要新的演奏法记号，或在 `model:` 里选拨弦方式）；手指拨弦时加手指碰弦、指甲声等起音细节。
  - 物理细节：张力调制目前只是线性滑回音准，可以改成随振幅变化；加弦打品的“咔啦”声（重拨或低把位时明显）；圆缠弦和平缠弦的音色差别。
  - 拾音器和放大器：P / J 拾音器可选；放大器加压缩和 DI + 箱体两路混合，让低频更稳、在乐队里更清楚。
  - 混音：贝斯和底鼓的低频分工（侧链或均衡），现在只靠自动电平。

### Hammond 风琴的改进方向（v1 之后）

v1 试听“挺好”，但还没有用真实录音校准，参数来自 B-3 / 122 的公开资料和频谱检查。可能的改进：

- **调音色**（最可能先动的几项）：Leslie 调幅深度（号角对纯音约 15 dB，可能偏深）；过载曲线和 `drive` 的手感；喀哒声的默认大小；整体亮度（`rock` 预设只开低音的 4 根拉杆，比旧版暗不少）；预设的拉杆组合可以对照名曲再调。

- **Leslie**：刹车（停转）；小节中间切换快慢（需要记谱或演奏层的标记）；箱体和房间更真实的反射（现在是每支话筒两三条固定路径）；号角的指向性随频率变化；122 功放用电路级建模。
- **音轮和触点**：音轮滤波电容和匹配变压器的频响；更完整的串音组合（现在只有同一隔间的 ±24、±48 个音轮）；松键喀哒声和按键喀哒声分开调；打击泛音的 soft / normal 音量。
- **扫描颤音**：用真实 LC 延迟线的抽头和扫描器的阶梯感，代替连续的调制延迟。
- **表情踏板**：音量低时保留低频（B-3 踏板的低音补偿）；小节内的踏板曲线（渐强、渐弱）。
- **编制**：下层键盘和脚踏低音键；两层键盘用不同的音栓配置。
- **校准**：对着真实 B-3 + Leslie 录音调 Leslie 调幅深度、多普勒幅度和过载曲线，最终以盲听 A/B 为准。
- **Rhodes**：下一件键盘乐器，需要先决定 DSL 是新增乐器类型还是 `piano` 的另一个引擎。

## 评测记录

- **2026-10-03 试点**（Sonnet，5 个任务 × 3 次，`evals/results/20261002-2329-sonnet-pilot/`）：15/15 最终通过校验；转写和修错任务 F1 全部 1.0；修改任务 12/12 项检查通过。
  - 最常见错误：鼓网格多写或少写一个字符（第一次检查时 6 个错误）。
  - 15 次里 12 次想用 python 筛选 `beat events` 的输出。
  - t1、t2、t4 对 Sonnet 太简单，分数到顶；还没有衡量“好不好听”。
- **2026-10-04 Haiku 下限**（规格和工具已按试点改进，`evals/results/20261003-2154-haiku-floor/`）：14/15 最终通过校验（失败的 1 次是评测框架问题：它用 `./.bin/beat` 调用，被权限拦下后放弃）；修改 12/12、修错 F1 ≈ 1.0、创作 8/8，但**转写 F1 只有 0.81–0.82**。
  - 校验能抓的错误 Haiku 最终都改好了（网格长度错误 329 个、记号错误 309 个，平均 6–8 轮），但花费和时间是 Sonnet 的 2–3 倍。
  - 失分全是**能通过校验的错误**：鼓击打放错了步（例如底鼓放在第 2 拍而不是第 2.5 拍；三连音叮叮镲被写进 16 步网格）；2.5 拍、6 拍这类时值被截成 2 拍、4 拍（没用连音线拼）；时值沿用导致四分音符写成八分音符。
  - 结论：网格记谱和“只能用连音线拼时值”对小模型代价很高，且错误会悄悄通过校验。这是对两项待决定改动（任意时值写法、按拍位写鼓）的有力证据。
- **2026-10-04 Haiku A/B：`hits` + `:b`**（`evals/results/20261004-0311-haiku-ab-hits/`，对照组为上一条）：t1 F1 0.82 → 0.95，t2 F1 0.81 → 0.98；6 次全部用 `hits`、无一次用 `grid`；平均用时约 10.5 → 5 分钟，花费 0.87 → 0.40 美元。
  - 剩余失分：一次把三连音位置写成 `1.667`（已改为报错）；个别鼓件放错、2.5 拍的音仍被写短一次。
  - 评测框架问题：Agent 用 `.bin/beat` 调用被拦截，已放行该写法并在提示里说明直接用 `beat`；受影响的那次已重跑。
- **2026-10-04 Sonnet：`beat voicing` + `add` + `replace` 里的 `transpose`**（`evals/results/20261004-1755-sonnet-voicing-add/`，对照组为试点）：t3、t4 都是 3/3 通过、任务检查全满分，和试点持平（试点已到顶）；花费 t3 0.47 → 0.54、t4 0.26 → 0.21 美元。
  - 新功能都被用上了：t4 三次都用 `beat voicing` 查强力和弦和风琴排列；t3 三次都用 `add` 在段落开头加吊镲，1 次用 `replace` + `transpose` 把同一 riff 搬到三个和弦上，1 次用了 `beat voicing`。
  - 出现过的错误都和新功能无关（outro 的 `hits` 多段写法、照抄示例的 performance edit），而且最终都改好了。
  - Agent 的愿望：`beat voicing` 能指定音区或靠近某个音（`--near`），方便和前后的排列衔接。
