# Beat 规格 v0.1（初版）

本文档定义三件事：

1. **歌曲文件格式（Beat DSL）**：LLM / Agent 写的、人可以编辑的唯一“源文件”。
2. **编译产物（事件表）**：DSL 编译后的中间表示，供渲染器、MIDI 导出和编辑界面使用。
3. **命令行工具**：Agent 用来校验、试听和分析的接口。

v0.1 的目标是**跑通“写 → 校验 → 听”的闭环**，只覆盖摇滚乐队。凡是标注“v0.1 不支持”的内容，都会在规格里留好位置，以后再实现。

---

## 1. 设计原则

- **对 LLM 友好**：使用 YAML 和紧凑的文本记谱，避免逐音符的冗长 JSON；常见写法（八分音符的贝斯、重复的鼓型）要写得短。
- **可严格校验**：每条错误都要指明位置（段落、声部、小节），并说明原因，让 Agent 能据此修改。
- **分层**：`sections`（谱面，作曲意图）、`performance`（演奏细节）、`mix`（混音）三层互相独立。修改演奏和混音不会改动谱面。
- **结果可复现**：同一个文件，加上同一个 `seed`，渲染结果完全一致。
- **可回溯**：编译后的每个事件都记录它来自源文件的哪个位置，编辑界面以后可以据此双向同步。

---

## 2. 文件结构总览

一首歌就是一个 `.beat.yaml` 文件：

```yaml
beat: 0.1                 # 规格版本，必填

meta:
  title: Demo Riff
  tempo: 120              # BPM，以四分音符为一拍
  time: 4/4               # 拍号（v0.1 全曲只能有一个拍号）
  key: E minor            # 用于分析，不影响编译
  style: hard rock        # 自由文本，给 Agent 和人看

instruments:              # 乐队编制：声部 id → 乐器
  dr:  { type: drums }
  bs:  { type: bass }
  gt1: { type: guitar, tone: crunch }
  gt2: { type: guitar, tone: lead }
  org: { type: organ }

patterns: { ... }         # 可复用的片段（可选）
sections: { ... }         # 段落：谱面的主体
form: [intro, verse, chorus, verse, chorus, outro]   # 段落的播放顺序

performance: { ... }      # 演奏层（可选）
mix: { ... }              # 混音层（可选）
```

## 3. 乐器（`instruments`）

键是**声部 id**（小写字母开头，可以包含字母、数字和下划线），全曲都用它引用这个声部。

| type | 说明 | 默认音域 | 主要参数 |
|---|---|---|---|
| `drums` | 鼓组 | — | — |
| `bass` | 电贝斯 | 由调弦和品数决定 | `tuning`（默认 `[E1, A1, D2, G2]`）、`frets`（默认 21） |
| `guitar` | 电吉他 | 由调弦和品数决定 | `tuning`（默认 `[E2, A2, D3, G3, B3, E4]`）、`frets`（默认 22）、`tone`：`clean` / `crunch` / `lead`（默认 `crunch`） |
| `organ` | Hammond 类风琴 | C2–C7 | — |
| `piano` | 钢琴 | A0–C8 | — |

- 调弦按从低音弦到高音弦的顺序写。降调直接改 `tuning`，例如 Drop D：`[D2, A2, D3, G3, B3, E4]`。
- `model:` 字段预留给合成器参数（自由结构，原样传给合成器）。v0.1 的合成器会忽略它。

## 4. 音高声部的记谱（`notes`）

用于 `bass`、`guitar`、`organ`、`piano`。

### 4.1 基本规则

- 一个 `notes` 字符串覆盖若干小节，小节之间用 `|` 分隔。
- 小节里的记号用空白分隔。
- 每个小节的时值总和必须**恰好**等于一个小节的长度，否则报错。

### 4.2 记号

| 写法 | 含义 | 例子 |
|---|---|---|
| 音名 + 八度 | 单音，科学音高记法，中央 C = `C4` = MIDI 60 | `E2`、`F#3`、`Bb4` |
| `[...]` | 和弦（同时发声） | `[E2 B2 E3]` |
| `r` | 休止 | `r:4` |
| `:时值` | 时值：`1 2 4 8 16 32`，后面可以加 `.`（附点）、`t`（三连音，即 ×2/3） | `E2:8`、`A2:4.`、`C4:8t` |
| `:b拍数` | 直接写以拍为单位的时值（一拍 = 四分音符），可以是小数或分数 | `E2:b2.5`、`C4:b1/3`、`r:b1.5` |
| `~`（写在音符末尾） | 连音线，延续到下一个相同音高的音 | `E2:2~ \| E2:1` |
| `!演奏法` | 演奏法标记，可以叠加 | `E2:8!pm!acc` |
| `@力度` | 改变后续音符的力度：`ppp pp p mp mf f ff fff` | `@f E2:8` |
| `( ... )*n` | 把一组记号重复 n 次（不能跨小节） | `(E2:8!pm)*8` |
| `%` | 整小节重复上一小节 | `E2:1 \| %` |

**时值和力度会沿用前一个音的设置**：如果省略，就使用同一个 `notes` 字符串中前一个音的值。字符串开头的默认值是四分音符和段落的默认力度。

**演奏法不会沿用**：`!pm` 等只作用于它所在的那个音（或和弦）。八个闷音要写八次 `!pm`，或者用 `(E2:8!pm)*8`。

**任意时值**：用 `:b拍数`，例如 2.5 拍写成 `E2:b2.5`。一个音不能跨过小节线：跨小节的长音在小节线处断开，用连音线接到下一小节，例如从小节开头持续 6 拍写成 `E2:b4~ | E2:b2`。连音线也可以跨段落：只要曲式里下一个段落的同一个声部，开头接着同音高的音即可。

### 4.3 演奏法

| 标记 | 含义 | 适用乐器 | v0.1 渲染 |
|---|---|---|---|
| `!pm` | 闷音（palm mute） | guitar, bass | ✅ |
| `!x` | 死音（按弦不出音高） | guitar, bass | ✅ |
| `!st` | 断奏 | 全部 | ✅ |
| `!acc` | 重音 | 全部 | ✅ |
| `!h` / `!p` | 击弦 / 勾弦（相对前一个音） | guitar, bass | ⏳ 只当作弱拨 |
| `!sl` | 从前一个音滑到这个音 | guitar, bass | ⏳ 忽略 |
| `!bend=N` | 推弦 N 个半音（可以是 0.5、1、2） | guitar, bass | ⏳ 忽略 |
| `!vib` | 揉弦 | guitar, bass | ⏳ 忽略 |
| `!harm` | 自然泛音 | guitar, bass | ⏳ 忽略 |

渲染器不支持的演奏法会被保留在事件表里，不会报错。乐器不适用的演奏法会产生警告。

### 4.4 例子

```
(E2:8!pm)*4 G2:8 E2 A2 B2 | (E2:8!pm)*8 | [E2 B2 E3]:2 [G2 D3 G3]:4 [A2 E3 A3] | [B2 F#3 B3]:1
```

## 5. 鼓的记谱（`hits` 或 `grid`）

鼓有两种写法，二选一：

- **`hits`（推荐）**：按拍位列出每个鼓件的击打，不用数字符。
- **`grid`**：步进网格，适合需要一眼看出整小节形状的密集节奏。

### 5.1 `hits`

```yaml
hits: |
  hh: every 0.5
  sd: 2!acc 2.75!ghost 4!acc
  bd: 1 2.5 3
```

- 每个鼓件一行；拍位从 1 开始，`2.5` 是第 2 拍的后半拍，`1.75` 是第 1 拍的最后一个十六分音符。三连音写成 `1+1/3`、`1+2/3`。
- 拍位后面可以加 `!acc`（重音）、`!ghost`（鬼音）、`!flam`（装饰音）。
- `every 步长` 表示从第 1 拍开始等间隔击打，例如 `every 0.5`（八分音符）、`every 1/3`（八分三连音）。
- 多个小节用 `|` 分隔，每个鼓件都要写满小节数；某个小节不打就留空，例如 `cr: 1!acc |`。

### 5.2 `grid`

鼓的**步进网格**，每个鼓件占一行：

```yaml
grid: |
  hh: x-x-x-x-x-x-x-x-
  sd: ----X-------X---
  bd: x-------x-x-----
```

- **步长**：默认每小节 `拍数 × 4` 步（4/4 拍就是 16 步，每步一个十六分音符）。可以用 `steps:` 改成每小节的步数，例如三连音的 shuffle 用 `steps: 12`。
- 每行的长度必须等于 `每小节步数 × 小节数`。行内的 `|` 和空格会被忽略，可以用来分隔小节，方便阅读。
- 没写出来的鼓件就是不演奏。
- **建议按拍用空格分组**，多小节时用 `|` 分隔小节，例如 `hh: x-x- x-x- x-x- x-x- | x-x- x-x- x-x- x-x-`。空格和 `|` 不计入步数；用 `|` 分隔后，长度错误会指出具体是哪一小节。

**字符含义：**

| 字符 | 含义 |
|---|---|
| `-` 或 `.` | 不击打 |
| `x` | 普通击打 |
| `X` | 重音 |
| `g` | 鬼音（很轻） |
| `f` | 装饰音（flam） |

**鼓件（lane）：**

| lane | 鼓件 | GM 音符 | 肢体 |
|---|---|---|---|
| `bd` | 底鼓 | 36 | 脚 |
| `sd` | 军鼓 | 38 | 手 |
| `ss` | 军鼓边击（side stick） | 37 | 手 |
| `hh` | 踩镲（闭合） | 42 | 手 |
| `ho` | 踩镲（打开） | 46 | 手 |
| `hp` | 踩镲踏板 | 44 | 脚 |
| `t1` / `t2` / `t3` | 高 / 中 / 落地嗵鼓 | 48 / 45 / 41 | 手 |
| `cr` / `cr2` | 吊镲 1 / 2 | 49 / 57 | 手 |
| `rd` / `rb` | 叮叮镲 / 镲帽 | 51 / 53 | 手 |
| `ch` | 中国镲 | 52 | 手 |

打开的踩镲会一直响，直到下一次 `hh` 或 `hp` 把它闭合，渲染器会模拟这一点。

## 6. 片段（`patterns`）

可复用的音乐片段：

```yaml
patterns:
  rock_beat:
    type: drums           # drums 或 pitched
    bars: 1
    grid: |
      hh: x-x-x-x-x-x-x-x-
      sd: ----X-------X---
      bd: x-------x-x-----
  riff_a:
    type: pitched
    bars: 2
    notes: "(E2:8!pm)*4 G2:8 E2 A2 B2 | (E2:8!pm)*8"
```

## 7. 段落（`sections`）

```yaml
sections:
  verse:
    bars: 8
    tempo: 120                    # 可选，覆盖全局速度
    dynamic: mf                   # 可选，本段落的默认力度（默认 mf）
    chords: "Em | Em | C | D | Em | Em | C D | B7"   # 可选，用于校验和分析
    parts:
      dr:
        use: rock_beat            # 引用片段；片段比段落短时会循环填满
        replace:                  # 用新内容替换某些小节（从 1 开始计数）
          8: { grid: "sd: --x-x-xxX-X-XXXX\nbd: x---------x---" }
        add:                      # 在原有节奏上叠加击打（只适用于鼓）
          1: { hits: "cr: 1!acc" }
      bs:
        use: riff_a
        transpose: 0              # 可选，移调（半音数），只适用于音高声部
        replace:
          5-6: { use: riff_a, transpose: 5 } # replace 里也可以移调，只作用于这几个小节
      gt1:
        notes: "..."
      # 没有列出的声部在本段落中不演奏

  verse2:
    extends: verse                # 继承 verse 的全部设置
    parts:                        # 只覆盖列出的声部
      gt2: { notes: "..." }
```

**内容来源**：每个声部的内容必须在以下几种方式中选**一种**：`notes`（音高声部）、`hits` 或 `grid`（鼓）、`use`。另外可以加 `replace`，鼓还可以加 `add`。片段（`patterns`）、`replace` 和 `add` 里也可以用这几种写法。

**`replace`**：键可以是 `8`，也可以是范围 `5-6`。值是 `notes`、`hits`、`grid` 或 `use`（引用片段，例如可复用的鼓加花）中的一种，长度必须等于被替换的小节数。

- 替换是**整小节**的：鼓的小节被替换后，新内容里没写的鼓件在这些小节不演奏。
- 替换的 `grid` 可以有自己的 `steps:`，例如在 16 步的鼓谱里单独放一个三连音小节：`replace: { 1: { steps: 12, grid: "rd: x-xx-xx-xx-x" } }`。
- 替换内容可以有自己的 `transpose:`，例如把同一个 riff 搬到别的和弦上：`replace: { 5-6: { use: riff_a, transpose: 5 } }`。
- 声部的 `transpose` 只作用于主体内容（`notes` 或 `use`），不作用于 `replace` 进来的内容。

**`add`**（只适用于鼓）：键的写法和 `replace` 一样，值是 `hits`、`grid` 或 `use` 中的一种。新的击打**叠加**在这些小节原有的节奏上，原有的击打保持不变。最常见的用法是在段落开头加一下吊镲：`add: { 1: { hits: "cr: 1!acc" } }`。

- 先做 `replace`，再做 `add`，所以 `add` 叠加在替换后的内容上。
- 同一个鼓件在同一拍位已经有击打时报错。要改掉原有的击打（例如去掉第 1 拍的踩镲），用 `replace` 重写这一小节。
- 叠加后仍然要满足“同一时刻最多 2 只手”。吊镲和踩镲、军鼓同时落在一拍上时，要用 `replace` 把踩镲去掉。

**`dynamic`**：声部也可以单独设置默认力度，覆盖段落的 `dynamic`。

**YAML 引号**：以 `[`、`(`、`%`、`@`、`!` 开头的 `notes` 字符串必须加引号，否则 YAML 会把它读成别的东西。多行内容可以用 `>-` 或 `|` 块。

**`chords`**：和弦记号的格式和 `notes` 一样，用 `|` 分隔小节，一个小节里可以有多个和弦，平均分配时长。

- 支持的写法：`C`、`Cm`、`C7`、`Cmaj7`、`Cm7`、`Cdim`、`Caug`、`Csus2`、`Csus4`、`C5`、`Cadd9`、`C6`、`Cm6`，以及转位 `C/E`。
- `N.C.` 表示没有和弦。

**`extends`**：被继承的段落不能再有 `extends`（v0.1 只支持一层继承）。`parts` 会按声部合并，其他字段直接覆盖。

## 8. 曲式（`form`）

由段落 id 组成的列表，同一个段落可以出现多次。同一个段落第 n 次出现时，称为它的第 n 个**实例**（instance，从 1 开始），演奏层的编辑会用到这个编号。

## 9. 演奏层（`performance`）

谱面写的是“写了什么”，演奏层写的是“怎么演”。

```yaml
performance:
  seed: 42                         # 随机种子，保证结果可复现
  humanize:                        # 全局的人性化处理
    timing_ms: 6                   # 起音时间随机偏移的标准差（毫秒）
    velocity: 0.05                 # 力度随机偏移的标准差（力度范围是 0–1）
  swing: { amount: 0.5, grid: 8 }  # amount=0.5 是直拍，0.67 接近三连音的摇摆感
  parts:
    dr:
      humanize: { timing_ms: 4 }
      lanes:                       # 鼓件级别的设置
        sd: { offset_ms: 8 }       # 军鼓整体靠后（laid-back）
        hh: { velocity: -0.05 }
    bs: { offset_ms: 4, velocity: 0.0 }
    gt1: { strum_ms: 8 }           # 和弦从低音到高音依次延迟（扫弦）；吉他默认 8
  edits:                           # 逐音修改
    - part: gt1
      section: chorus
      instance: 2                  # 可选；省略时作用于所有实例
      bar: 4                       # 段落内的小节号，从 1 开始
      beat: 3                      # 小节内的拍位，从 1 开始；2.5 表示第 2 拍的后半拍
      pitch: B3                    # 可选（音高声部）；省略时作用于该位置的所有音
      # lane: sd                   # 鼓用 lane 代替 pitch
      velocity: 0.9                # 绝对值；也可以写 "+0.1" 或 "-0.1"
      offset_ms: -10
      length: 1.2                  # 时长倍数
```

- 处理顺序：先应用谱面力度，然后依次是声部和鼓件的偏移、扫弦、swing、edits，最后做 humanize。
- 同一个和弦的各个音共用一个 humanize 时间偏移，所以扫弦顺序不会被打乱；力度偏移仍然逐音独立。
- `!st`（断奏）会把演奏时长减半。
- **没有匹配到任何音符的 edit 会报错**（例如谱面改了以后，edit 失去了目标）。这样修改谱面后，过时的演奏修改不会悄悄失效。

**力度对照**（0–1）：

| ppp | pp | p | mp | mf | f | ff | fff |
|---|---|---|---|---|---|---|---|
| 0.15 | 0.25 | 0.38 | 0.50 | 0.63 | 0.78 | 0.90 | 1.0 |

- 重音（`!acc` 或 `X`）：+0.12
- 鬼音（`g`）：×0.35
- 结果限制在 0.05–1.0 之间

## 10. 混音层（`mix`）

```yaml
mix:
  dr:  { gain_db: 0,  pan: 0 }
  bs:  { gain_db: -1, pan: 0 }
  gt1: { gain_db: -3, pan: -0.7 }     # pan 的范围是 -1（左）到 1（右）
  gt2: { gain_db: -3, pan: 0.7 }
  master: { gain_db: 0 }
```

v0.1 只支持 `gain_db` 和 `pan`。渲染器会先做**自动增益**：把每个声部归一化到各乐器类型的目标 RMS（鼓 -16、贝斯 -18、吉他 -20、风琴 -25、钢琴 -21 dBFS），再应用 `gain_db`，所以 `gain_db` 是相对于这个默认平衡的调整。最后会把主输出的峰值归一化到 -1 dBFS。EQ、压缩和混响以后再加。

## 11. 编译产物：事件表

`beat events song.beat.yaml --json` 会输出：

```json
{
  "meta": {"title": "...", "duration_sec": 32.0, "bars": 16},
  "parts": {"gt1": {"type": "guitar", "tone": "crunch"}},
  "events": [
    {
      "part": "gt1",
      "time": 2.0, "dur": 0.25,          // 秒
      "beat": 4.0, "beats": 0.5,         // 从曲首开始计算的拍数
      "pitch": 40,                       // MIDI 音符号；鼓是 GM 鼓音符号
      "lane": null,                      // 鼓件名；音高声部为 null
      "velocity": 0.63,
      "arts": {"pm": true},
      "src": {"section": "verse", "instance": 1, "bar": 1, "beat": 1.0, "global_bar": 5}
    }
  ]
}
```

## 12. 校验规则

**错误（必须修正）：**

- 结构错误：缺少必填字段、引用了不存在的声部、片段或段落、片段类型和乐器不匹配、内容来源冲突
- 小节数不对，或者小节的时值总和不对
- 网格长度不对
- 无法识别的音名或时值
- 连音线连到了不同的音高，或者后面没有音可连
- 音高超出乐器音域
- **吉他和弦无法演奏**：找不到把每个音分配到不同的弦、并且最高品和最低品相差不超过 4（空弦除外）的指法
- **鼓手手不够用**：同一时刻需要的手超过 2 只（`f` 装饰音算 2 只手）
- 演奏层的 edit 没有匹配到任何音符

**警告（建议修正）：**

- 贝斯同时发出超过 2 个音
- 乐器不适用的演奏法（例如风琴的 `!pm`）
- 强拍上的贝斯音不在当前和弦里
- 片段循环填满段落时没有整除（最后一次被截断）

## 13. 命令行工具

```
beat validate SONG [--json]                  校验；有错误时退出码为 1
beat events   SONG [--json] [--parts a,b] [--sections x,y] [--bars 5-8] [--by-bar]
                                             输出编译后的音符；--by-bar 是逐小节的紧凑视图
beat midi     SONG -o out.mid                导出 MIDI
beat render   SONG -o out.wav [--parts gt1,bs] [--sections verse,chorus]
beat voicing  CHORD [full|power] [--for guitar|bass|organ|piano] [--tuning D2,A2,...] [--low C3] [--max 6] [--json]
                                             列出和弦的可演奏排列，复制到 notes 里用
beat analyze  SONG [--json]                  （v0.2）乐理和音频分析报告
```

- 加 `--json` 时输出机器可读的结果，供 Agent 使用；不加时输出给人看的文本。
- 每条诊断信息的格式：`[error] verse#1 > bs > bar 3: duration 3.5 beats, expected 4`

**`beat voicing`**：DSL 本身不会根据 `chords` 自动生成和弦排列（文件里写什么就演奏什么），这个命令只是查询工具。

- 吉他、贝斯：列出能按出来的指法，每行是指法图（从低音弦到高音弦，`x` 表示不弹）和对应的音，例如 `x02210  [A2 E3 A3 C4 E4]`。排列一定满足第 12 节的可演奏规则：最低音是根音（转位和弦是 `/` 后面的音），用相邻的弦，按“容易弹、音多”排序。`--tuning` 用于降调等非标准定弦。
- `full`（默认）：包含和弦的所有音；四个音以上的和弦可以省略五音。`power`：根音、五度、八度（强力和弦），和弦里没有纯五度时报错。
- 风琴、钢琴：从 `--low` 往上的密集排列，列出原位和各个转位。
